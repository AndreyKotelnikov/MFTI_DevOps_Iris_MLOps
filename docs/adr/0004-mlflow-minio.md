# 4. Почему используем MLflow и MinIO для трекинга экспериментов

Date: 2025-12-03

## Status

Accepted

## Context

Нужно:
- отслеживать эксперименты (метрики, параметры, версии модели);
- хранить артефакты (pickle-файлы моделей, отчёты мониторинга и др.);
- иметь возможность локального развёртывания без облачных сервисов.

Варианты:
- только локальные файлы, без специализированного инструмента;
- встроенные возможности scikit-learn / самописные логи;
- MLflow + локальное файловое хранилище;
- MLflow + S3-совместимое хранилище MinIO.

## Decision

Используем **MLflow** как систему трекинга и регистрации моделей, а **MinIO** как S3-совместимое хранилище артефактов, поднятое в том же `docker-compose` стенде.

### Обоснование

1. **Единый интерфейс для экспериментов.**  
   Файл `src/models/train.py` логирует параметры, метрики и саму модель в MLflow.

2. **S3-совместимость и переносимость.**  
   MinIO работает локально, но даёт S3 API, что упрощает миграцию в облако.

3. **Простая интеграция в Docker Compose.**  
   В `docker-compose.yml` достаточно добавить сервис `minio` и прокинуть
   переменные `MLFLOW_S3_ENDPOINT_URL`, `MLFLOW_S3_BUCKET` в `mlflow`.

4. **Учебная ценность.**  
   Студенты видят реальный пример связки `MLflow + S3`, типичный для продакшн-проектов.

## Consequences

- Нужно поддерживать минимальную конфигурацию MinIO и бакетов для проекта.
- В Yandex Cloud / другом облаке придётся либо поднимать MinIO, либо переключаться на нативное S3-хранилище и обновлять настройки.
- Метрики и артефакты теперь живут вне git; их нужно бэкапить и чистить отдельно.
