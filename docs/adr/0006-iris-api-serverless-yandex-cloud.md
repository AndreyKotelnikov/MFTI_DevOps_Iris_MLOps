# 6. Почему деплоим iris-api как serverless-контейнер в Yandex Cloud

Date: 2025-12-03

## Status

Accepted

## Context

Нужно показать пример:
- сборки отдельного Docker-образа только с API и моделью;
- публикации образа в Yandex Container Registry;
- деплоя как serverless-контейнера (минимальная инфраструктура).

В проекте уже есть:
- `deploy/Dockerfile.api` — облегчённый образ только с API и моделью;
- `deploy/deploy_to_yc.ps1` — скрипт, который собирает образ, пушит его и разворачивает контейнер.

## Decision

Для продакшн-/демо-деплоя iris-api используем:
- образ, собранный по `deploy/Dockerfile.api`;
- Yandex Cloud Serverless Containers, управляемые через CLI `yc` и скрипт `deploy/deploy_to_yc.ps1`.

### Обоснование

1. **Разделение dev и prod образов.**  
   Основной `Dockerfile` — для локальной разработки и docker-compose-стенда, `deploy/Dockerfile.api` — для продакшн-запуска.

2. **Serverless-модель.**  
   Нет необходимости поднимать и обслуживать отдельный VM/кластеры для маленького сервиса.

3. **Скрипт деплоя как документация.**  
   `deploy_to_yc.ps1` фиксирует шаги деплоя и упрощает повторяемость.

## Consequences

- Скрипт завязан на Yandex Cloud CLI и переменные окружения (`YC_SA_ID`, `YC_FOLDER_ID`, `RegistryId` и т.п.).
- При переходе в другое облако потребуется новый ADR и переосмысление процесса деплоя.
- Важно поддерживать актуальность `deploy_to_yc.ps1` при изменении параметров сервиса (порт, переменные, ресурсы).
